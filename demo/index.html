Before and after, at every speed

How long the voice kept going after cancel() returned. The faster the server makes audio, the more of the reply is already waiting to play when you cut in.

The fix is a thin wrapper

It uses only the public SDK. It keeps its own interrupted flag, drops audio that is already queued, and still reads the turn to its normal end.

  • Covers audio already sitting in the context queue.
  • Covers the case where the server already sent task_done, so cancel() does nothing.
  • 10 tests in the repo reproduce both gaps and the fix.
# before: async for event in ctx
turn = Interruptible(ctx)
async for event in turn:
    if isinstance(event, AudioEvent):
        speaker.write(event.pcm)

# on barge-in, before: await ctx.cancel()
await turn.interrupt()

Second check: time to first audio

The LLM pauses for 1.0 s in the middle of its first sentence. Flam's Visual Agents page puts the whole pipeline under 800 ms.

These numbers mostly echo the mock's own settings (150 ms per sentence) plus the idle flush timer. They show why the timer matters, not how fast Finesse is.

How it was measured

The real, unmodified flam-finesse 0.1.1 Python SDK, run against a local mock of the Finesse realtime WebSocket. No API key, no network. Show detailsHide details
Server
A local mock (finesse_mock.py) written from the SDK's message parser and README. It is not Flam's service, so no number here is a measurement of Finesse.
Player
Plays in real time by sleeping for each chunk's duration, the same back pressure a blocking speaker.write creates.
Barge-in
After 1.0 s of played audio the user starts talking and the player calls ctx.cancel() (README pattern) or turn.interrupt() (wrapper).
Stale speech
Seconds of this turn's audio the player still received and played after the cancel call returned.
Silence latency
Wall time from the cancel call returning to the last audio chunk finishing playback.
Why speed matters
The faster synthesis runs ahead of playback, the more audio is already buffered in the context's queue when the user cuts in. At 8x the server had already sent task_done, so cancel() returned early and the whole rest of the turn played.

Honest limits

  • Real Finesse timing, sentence splitting and idle flush may differ from the mock.
  • Whether the gap shows in production depends on how far real synthesis runs ahead of playback, which was not measured without an API key.
  • Only the Python SDK was checked. The Node SDK and the LiveKit and Pipecat plugins were not tested.
  • Local loopback has no network delay. Playback is a sleep, not a speaker or a lip sync renderer.
